## Problem

`InsertRestockingLineItemVersion` took `created_at` from `NOW()`, which is fixed at BEGIN. A restock signal whose
repeatable-read transaction began before another signal committed version 2 saw version 2 in its snapshot, appended
version 3, and stamped it before version 2. Every latest-version read orders by `created_at DESC, version DESC`, so
it returned version 2, and each later signal collided on version 3 until `VersionConflict`. The line stayed blocked.
A writer clock ahead of the database's did the same through version 1, which the writing process stamps.

## Change

The query stamps `GREATEST(NOW(), MAX(created_at) + 1 microsecond)` over the line's versions, as sc-4089 does for
order line items. The subquery reads the transaction snapshot, so it sees version 2.
`idx_restocking_line_items_latest_version` serves it. `id` is `CHAR(26)`, so the cast is `::char(26)`. All append
paths inherit the stamp; no call site changes.

Two integration tests:

- `Test統ProcessRestockSignal_ConcurrentVersionDoesNotBuryTheNextOne` holds transaction A between BEGIN and its first
  statement while signal B commits version 2, then lets A commit version 3. The lookup must return version 3, and a
  later signal must append version 4.
- `Test統InsertRestockingLineItemVersion_StampsAfterThePreviousVersion` stamps version 1 an hour ahead of the database
  clock and checks the exact +1 µs and +2 µs steps of versions 2 and 3.

## Verification

- Both tests fail on the query without the fix and pass with it.
- `make build`, `make lint`, `make test`, `make sqlc-diff`, `make lint-prose`, `make lint-docs`: pass.
- `make integration-test SHARDS=inventory-service`: pass.
- A Quint model of the three concurrent append paths (restock, short-close, cancel) breaks `latestIsNewest` on the
  merge base and holds it, with `createdAtFollowsVersion`, `versionsContiguous` and `lookupsAgree`, on this branch
  (50,000 samples × 60 steps).

## Not in this PR

- Lines already blocked in production stay blocked: this change repairs no existing data.
- Ordering the latest-version reads by `version` instead of `created_at` would remove the dependency on clocks. It
  needs a migration and the same change on order line items, and it changes query plans on hot reads, so it is not
  part of this fix.
