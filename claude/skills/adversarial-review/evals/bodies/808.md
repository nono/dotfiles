## Causes and changes

| Cause | Change |
|---|---|
| Each shard runs `go vet ./...` (70 s), then compiles with `-p 1` (74 s). `-p 1` also serialises compilation. | The script compiles the shards' test binaries in parallel (`go test -race -exec /bin/true`) before the `-p 1` run. |
| setup-go keys its cache on `go.sum` alone. The main entry dates from 2026-09-21 and has no `-race` or `-cover` objects, so every job compiles from scratch. | Lint, Unit Tests and the shards each restore a cache of their own, through the new `go-cache` composite action. Only main saves. |
| Unit Tests runs `go build ./...` (60 s) without `-race`; `go test` compiles again. | Moved to Lint as `make build`, which also links the main packages. |
| sqlc diff, check-deps and vulncheck (30 s) run in Unit Tests. | Moved to Lint, which ends 6 min early. |
| `Test統NewPlanHandlerIntegration` takes 299 s; its three `_long` subtests take 157 s in real time. | New shard `agents-controller-long`. |
| The metascheduler shard runs `Test統FullReschedule` (162 s) after the other tests. | New shard `metascheduler-reschedule`. |

Also:

- `-count=1` on the unit and integration `go test` commands, so a test result in a restored cache cannot replace a
  run.
- The shards share one build cache: they all compile with `-race` and the `integration_tests` tag. A main-only
  Integration Cache job, off the critical path, fills it with `scripts/integration-tests.sh --build-only` (43 s and
  791 MB locally).
- A shard that runs no test fails. `go test` passes when the run filter matches nothing, so a renamed test would
  leave a split shard green and empty. The check needs a test at the depth of the filter, because `go test` runs
  the parent of a subtest filter even when no subtest matches.
- The deleted `go vet` step was the only one that reported `stdmethods` and `unsafeptr`: golangci-lint's `legacy`
  preset hides them (EXC0004). `.golangci.yml` now lists the preset's other rules and drops that one.
- The checks in Lint run after a golangci-lint failure too (`!cancelled()`).

## Risk

Main saves 3 caches per push (Lint, Unit Tests, integration). GitHub evicts the oldest entries past the 10 GB
repository limit. The composite action, the cache save and the Integration Cache job run only on main, so the first
run after the merge tests them.
