## Problem

`go test -race -count=3 ./tmplt-agent/simulation/preflight` stopped with `fatal error: reset of synctest timer from outside bubble` ([sc-5193](https://app.shortcut.com/template-systems/story/5193)).

go-deadlock v0.3.9 pools the timer of each lock wait in a `sync.Pool`. A timer made inside a `synctest` bubble went back to the pool. A later lock outside the bubble took it and called `Reset`, and the runtime stopped the process. With `-count=1` the file order hid the bug: every lock outside a bubble ran before the synctest tests.

## Change

- Disable the go-deadlock timer pool in the preflight `TestMain`. `tgxcli/internal/statistics` and `tgxcli/cmd/autopick/handlers` already did this.
- Add `TestDeadlockLockOutsideBubbleAfterSynctest`. It locks a go-deadlock mutex in and out of bubbles on one P, with an empty pool. Without the setting it stops the test binary in every run, so `make test` and CI fail if the setting goes away.
- Move the setting to `testutils.DisableDeadlockTimerPool`, and use the `TestMain` → `testMain(m) int` pattern in the three packages.

Not in this PR: a repo-wide fix, such as `-tags deadlock_synctest` in the test targets. It changes lock behaviour for every package and in CI. The other synctest packages pass `-race -count=3` as they are.
