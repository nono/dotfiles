Go test output is shorter for coding agents. The runs go through gotestsum v1.13.0, pinned as a module tool (`go tool gotestsum`).

## Changes

- `make test` prints through `gotestsum --format pkgname-and-test-fails --format-hide-empty-pkg`. A package with no tests prints no line. The flags stay the same: `-race -timeout=10m -failfast ./... -coverprofile=coverage.out`.
- `make test-rerun` is new and runs locally only. It uses `--rerun-fails` (2 reruns), so a flaky test shows as `(re-run N)` in the output and is not hidden. It drops `-failfast`, because gotestsum refuses it with `--rerun-fails`. It also drops `-coverprofile`, because a rerun would overwrite the profile with the coverage of the rerun only. The packages go only in `--packages`: a package list after `--` would reach each rerun and run the failed test's name, and every `TestMain`, in all packages.
- `scripts/integration-tests.sh --stream` (used by `make integration-test` and CI) pipes the shard through gotestsum, with the same flags. The `go test` argv does not change: tags, `-p 1`, `-run`/`-skip`, `-failfast -json -v`.
- `ci-logs/<shard>.json` and `.log` do not change. `go test` still writes to `tee "$json"`, and gotestsum reads a copy of that stream through `--raw-command -- cat`. I did not use `--jsonfile`, because gotestsum leaves non-JSON lines out of that file. The `.log` decoder still runs live. Its subshell holds the pipe to gotestsum open, so the pipeline ends only when the `.log` is complete.
- With `--stream`, the script no longer prints the last 60 lines of a failed shard's `.log`. gotestsum has already printed that output. Without `--stream`, the script prints the tail as before.
- New test `scripts/integration_tests_test.go`, which `make test` and the CI unit step run. A fake `go` on `PATH` replays a recorded `go test -json` stream through the script, and a slow fake `jq` makes the decoder finish late. The test checks the exit status, the `.json` byte for byte, the `.log` against an independent decoder, what a pass and a failure print, and that the 60-line tail prints only without `--stream`. 7 mutations of the script turn it red. It skips when bash is older than 5.1, because the script refuses to run there.
- The CI unit step (`ci-validation.yml`) prints through gotestsum with the same flags and the same `tee` method. Its log held the whole `go test -json` stream: 148,879 lines and 36.8 MB, which an agent reading `gh run view --log-failed` had to search. `unit-test-report.json` still gets every line, the `go test` argv does not change, and `coverage.out` has the same blocks. On a failure the step still exits 1 (the step sets `pipefail`).
- The CI unit step and the streamed shards also pass `--no-color`. In GitHub Actions gotestsum colors its output even into a pipe, and the escape codes (`^[[32m✓^[[0m`) end up in the log that `gh run view --log-failed` returns. `make test` keeps color for a human at a terminal; an agent reads it through a pipe and gets none.
- The format flags are in three places: the Makefile's `GOTESTSUM`, the script and the CI step. gotestsum has no environment variable for `--format-hide-empty-pkg`, and CI calls the script and `go test` without make. Each place names the other two.
- CLAUDE.md: 3 lines.

## Why `pkgname-and-test-fails` and not `testname`

On a passing, cached `make test`, `testname` printed 6,328 lines (539,641 bytes), one line per test and subtest. `pkgname-and-test-fails` printed 122 lines (8,422 bytes). Both formats show the full output of a failed test.

I also tried `--hide-summary=output` and did not keep it. It removes the second copy of a failed test's output, but it also removes the only copy of a TestMain failure's output and of a `-timeout` panic stack. The gotestsum summary is the only place that prints them.
