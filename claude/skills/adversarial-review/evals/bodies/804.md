## Summary

The Stop hook (`scripts/lint-changed-go.sh`) ran `make lint-fix`, which lints the whole module, after a
one-line change. It now runs the new target `make lint-fix-changed PKGS="..." FILES="..."`: the linters on
the packages that hold changed Go files (unstaged, staged, untracked), and the formatters on those files
only. A run that passed is not repeated until the state changes.

- Exact package paths (`./dir`), not `./dir/...`: the subpackages add analysis and find nothing more in the
  changed files.
- The changed files come from `git diff --no-renames HEAD -- '*.go'` and `git ls-files --others`, so a
  staged move also lists the package the file leaves. `core.quotePath=false` keeps a non-ASCII file name
  unquoted.
- The packages come from `go list -e -find ./...` (0.3-0.4 s), kept when their directory holds a changed
  file. So the hook follows the `./...` rules (testdata, vendor, hidden, `_`), and drops a deleted
  directory, a directory with only ignored or tag-excluded files, and a name that is not an import path:
  make and the shell never parse a directory name. A broken package is still linted. A test checks that
  the `go list` build tag matches `.golangci.yml`.
- Formatters on the changed files only: gci, gofmt, goimports and golines took 29% of the analysis CPU and
  checked every file of the package. They work file by file, so `golangci-lint fmt FILES` gives the same
  result. `run` gets `--enable-only=<the linters .golangci.yml enables>`, read from `golangci-lint
  linters`: `--disable` refuses a formatter. A file name outside ASCII letters, digits and `_./+~-` is not
  formatted (make or the shell could parse it); its package is still linted.
- Stamp: after a run that passes, the hook stores a hash of HEAD, the diff of the Go files and the lint
  configuration, and the untracked Go files, in the git dir. The next run with the same hash exits at once.
  The hook runs after every turn, and most turns change no Go file.
- No change to: `GOLANGCI_LINT_CACHE` (the target is in the Makefile), output on stderr, exit 2 blocks the
  stop, `make lint-fix` for a full run.
- `--new-from-rev=origin/main` is not used: it made the run slower (8.9 s against 8.5 s on
  `metascheduler/orders`).

Trade-off: a package that imports a changed package is not linted. A broken caller is a compile error that
`make build`, `make lint` and CI still catch.
